# Launcher & Projects

The **Ducz Launcher** is the front door: it manages your map projects, creates new
ones from templates and opens them in the [Map Builder](map-builder.md).

```bash
dotnet run --project src/Ducz.Tools.Launcher
```

## Opening a project that is already on disk

**Open from folder...** (next to *Create Project*) asks for a folder and adds it to the
project list, for maps that the launcher has never seen: copied from another machine, cloned
from git, or generated by a script.

- Pick the project folder itself, or its parent - the launcher looks one level down too.
- A folder with a `scenes/` directory but no `project.duczproj.json` is **adopted**: the
  missing project file is written (named after the folder) so it becomes a real project.
- The same thing happens if you pass a folder on the command line or drop it on the
  launcher's `.exe`:

```bash
Ducz.Tools.Launcher.exe "E:\Repos\Maps\MedievalCity"
```

The list itself lives in `%AppData%\DuczEngine\launcher.json`.

## Creating a project

Fill in the **New Map Project** form:

- **Name** - your map's name (also becomes the folder name).
- **Location** - where project folders are created (remembered for next time).
  Click **Browse...** to pick a folder with the native dialog, or type/paste a path.
- **Template** - the starting map:

| Template | Contents |
| --- | --- |
| **Empty Map** | Textured ground, sun, spawn point, player and camera - a blank canvas |
| **Arena** | Walled arena with a central platform, ramps, pillars with lights and physics crates |
| **Terrain** | Rolling hills terrain, fog, scattered crates and a campfire (light + particles) |

**Create Project** builds the folder and opens it in the Map Builder immediately.

## Project structure

```
MyMap/
  project.duczproj.json    project descriptor (name, main scene, engine version)
  scenes/main.json         the map (standard JSON scene format)
  Assets/                  models / audio you reference
  Assets/Textures/         images dropped or picked in the builder are copied here
  Export/                  MyMap.glb (default folder suggested by Export GLB)
```

The launcher and the map builder run **without a console window**; their messages go to
`%AppData%/DuczEngine/logs/launcher.log` and `mapbuilder.log` (check them if something fails).
The project list is stored per-user in `%AppData%/DuczEngine/launcher.json`.
**Open** launches the builder on a project; **X** removes it from the list
(files stay on disk).

## How the map builder uses projects

`Ducz.Tools.SceneEditor` accepts a project folder (or anything inside one):

```bash
dotnet run --project src/Ducz.Tools.SceneEditor -- path/to/MyMap
```

In project mode the builder:

- loads and saves the project's **main scene** (`scenes/main.json`),
- resolves relative asset paths against the **project folder** (so
  `Assets/Textures/wall.png` in the JSON just works),
- copies imported textures into `Assets/Textures/`,
- suggests `MyMap/Export/` in the **Export GLB** save dialog,
- shows the project name in the window title.

Passing a plain `.json` path still works for quick, project-less editing (textures are then
referenced by absolute path).

## Working with projects from code

```csharp
using Ducz.Export;
using Ducz.Serialization;

var project = ProjectFile.Load("path/to/MyMap");      // folder or file
var scene = SceneDocument.Load(project.MainScenePath);
GlbExporter.Export(scene, Path.Combine(project.Directory, "Export", "MyMap.glb"));
```
